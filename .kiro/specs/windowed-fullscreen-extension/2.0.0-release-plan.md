# 2.0.0 release plan

Working document for the 2.0.0 release of Windowed Fullscreen. Written to be picked
up cold: an agent with no memory of the conversation that produced it should be able
to read this file and carry on without asking what was decided or re-deriving it.

Read `.kiro/steering/product.md`, `.kiro/steering/tech.md`, `.kiro/steering/structure.md`
and `windowed-fullscreen-extension/AGENTS.md` first. This file does not repeat them.
Where this file and a steering file disagree, the steering file wins and this file is
out of date.

---

## 1. The decisions, and why

These are settled. Do not reopen them without being asked.

**Price is $10 once, not $5.** The Pro tier was built for $5 in an unreleased 1.4.0.
It never shipped, so there are no $5 buyers to honour and no grandfathering problem.
The larger feature set below is what justifies the price.

**The version goes 1.3.0 → 2.0.0.** 1.3.0 is the published version. A 1.4.0 was built
and never published, so its changelog section was folded into 2.0.0 rather than listed
as a release nobody could install. The store only requires the version to sort higher
than the published one, so the gap costs nothing. A major bump because three things
change what a returning reader must re-learn: a paid tier exists, the options page is
two tabs, and the docks carry settings of their own.

**Left-side docks were considered and dropped.** The user's words: not worth the work
load. Do not build a `--wfs-docked-left`, a side preference, or a mirrored rule set.
Everything docks on the right.

**Ambient glow does not violate the letterboxing rule.** `product.md` forbids cropping
and stretching video. Painting the bars does neither. `AGENTS.md` has a trap headed
"Letterboxing in windowed mode is correct" — glow honours that by making the bars
deliberate rather than by removing them. Keep `object-fit: contain`.

### The feature set

Paid, nine items. Three exist; six are new.

| Feature | State |
| --- | --- |
| Frame capture | Built in 1.4.0 |
| Dock resize by drag | Built in 1.4.0 |
| Per-channel auto-apply | Built in 1.4.0 |
| Channel profiles — a rule carries mode, panel state, dock widths | Phase 5 |
| Transcript dock | Phase 4 |
| Ambient glow in the letterbox bars | Phase 6 |
| Custom letterbox bar colour | Phase 6 |
| Capture filename template | Phase 7 |
| Capture with the timestamp burned into the image | Phase 7 |

Free, four items. This split was chosen deliberately over gating all thirteen: a
release this large with nothing for free users earns "the update is all paywall" in
the reviews, and none of these four is a reason anyone pays $10.

| Feature | Why it is free |
| --- | --- |
| Copy link at the current time | The mode hides `.ytp-overlay-top-right`, where YouTube's own share control lives. This repairs a loss the mode causes. Charging for a repair is poor form. |
| Export and import settings | It is the reader's own data, and it is the answer to why there is no `chrome.storage.sync`. |
| Cursor auto-hide when idle | Costs almost nothing and makes the free mode feel finished, which is what earns the install that later converts. |
| Hide the end-screen grid | `.ytp-ce-element` is already hidden for free. Add `.ytp-endscreen` to that same rule, with no toggle and no gate. A locked switch beside already-hidden cards is confusing, and a gate here reads as selling a suggestion blocker. |

### Cut, with the reason

**Deeper zen control bar** — hiding `.ytp-chrome-bottom` until the mouse moves. Cut
because that is the exact surface the `ytp-big-mode` reassertion machinery already
fights YouTube over. High regression risk against `verify:live` for a small win. Do
not add it back without deciding that risk is acceptable.

### What does not change

Not one feature in this release sends anything anywhere. Glow, transcript, capture and
export are all local. So **invariant 6 is untouched**: no new network call, no new
permission, no new host permission, and no change to the privacy policy, the store's
data-disclosure answers, or the listing's privacy paragraph. Say this in the listing;
for a release this size it is unusual.

## 2. State as of this document

`npm run check` is green: 151 tests, 151 pass, build emits. Phases 0 and 1 are
complete. Nothing is outstanding at the payment provider until release.

**Not yet run: `npm run verify:live`.** Phase 1 moved the dock width plumbing. That
script is the only thing in the project that sees layout, and it needs Chrome plus
network so it cannot run in CI. Run it before starting Phase 2. Widths should land
exactly where they did in 1.4.0, because the fitting order is unchanged: outboard to
inboard, each dock fitted against what the docks outside it actually took. If a pixel
moved, stop and find out why rather than building Phase 2 on top of it.

### Phase 0, done

- `DODO_API_BASE` is `https://test.dodopayments.com`. **This is correct.** See §5.
- `manifest.json` and `package.json` are both `2.0.0`.
- `CHANGELOG.md`'s 1.4.0 section is now `## 2.0.0` and explains the jump.
- Every `$5` string is `$10`: `HELP_COPY.pro.price`, `HELP_COPY.pro.buy`, and comments
  in `scripts/package.mjs` and `public/options/index.html`.
- `README.md` and `store-assets/LISTING.md` still say `$5`. Left for Phase 8, where
  their feature tables are rewritten anyway. **Do not forget them.**

### Phase 1, done

The stored preference shape changed. New symbols, all in `src/windowed-fullscreen.ts`:

| Symbol | Section | Note |
| --- | --- | --- |
| `DockId` | §1 | `"panel" \| "chat" \| "transcript"`. Moved here from §8. |
| `DOCK_IDS` | §1 | `["chat", "panel", "transcript"]`, **outboard to inboard**. Order is load-bearing. |
| `DockWidths` | §1 | `Readonly<Record<DockId, number>>`. 0 means "use the stylesheet's `clamp()`". |
| `DEFAULT_DOCK_WIDTHS` | §1 | Every dock at 0. |
| `ChannelRule` | §1 | `{ id, scrollable: boolean \| null, panel: boolean, dockWidths }`. |
| `SitePrefs.dockWidths` | §1 | Replaced `panelWidth` and `chatWidth`. |
| `SitePrefs.channels` | §1 | Now `readonly ChannelRule[]`, was `readonly string[]`. |
| `normalizeDockWidths` | §5 | Takes the **whole** stored record, not just its `dockWidths` field. |
| `newChannelRule` | §5 | The defaults a rule gets when it asks for no layout of its own. |
| `findChannelRule` | §5 | Returns the matched rule. `channelRuleMatches` is now a wrapper over it. |
| `YT_DOCKS` | §3 | `Partial<Record<DockId, {...}>>`. Per-dock selector table. **The place a dock is added.** |
| `YT_DOCK_ORDER` | §3 | `DOCK_IDS.filter(d => d in YT_DOCKS)`. Feeds `adapter.supportedDocks`. |
| `SiteAdapter.supportedDocks` | §1 | Which docks this site has. |
| `SiteAdapter.isDockActive` | §1 | Whether one of the **site's own** docks is taking width. |

Two things to understand about this, because they are what makes the rest safe.

**There is no migration step, and there must never be one.** `normalizeDockWidths`
falls back to the old sibling `panelWidth`/`chatWidth` fields when `dockWidths` is
absent, and `normalizeChannelRules` upgrades a bare string to `newChannelRule(id)`.
The upgrade happens on every read. Nothing runs once and is remembered as having run,
so nothing can fail halfway. `tests/prefs.test.ts` and `tests/pro-features.test.ts`
both pin this, including that reading an old record does not rewrite it.

**`DockId` already includes `"transcript"`, before the dock exists.** This is
deliberate and it is the tool for Phase 4: every exhaustive `Record<DockId, …>` in the
file becomes a compile error until the new dock is handled, so `tsc` is the checklist
rather than a hand-written list of call sites. `YT_DOCKS` has no `transcript` entry
yet, so `YT_DOCK_ORDER` excludes it, so no transcript grip mounts and no transcript
CSS is emitted. Behaviour is identical to 1.4.0.

Two invariant-2 leaks that were already in the tree got fixed on the way past. §9 no
longer hardcodes `["panel", "chat"]` when mounting grips, and `isDockVisible` no
longer queries `#chat` directly. Both go through the adapter now. Do not reintroduce
either.

## 3. Remaining phases

One feature per commit. `npm run check` green at every commit. `npm run verify:live`
after every phase, not at the end.

Phases are ordered so that cutting from the end is always possible. If a feature is
not ready, drop it and ship. **Phase 2 is the exception at the front**: the transcript
dock cannot exist without it.

### Phase 2 — the CSS token refactor

The only structural work left. The TypeScript side is already generic over `DockId`;
the stylesheet is not.

`YT_ACTIVE_MODE_CSS` in §3 hand-writes `--wfs-docked-width` once per combination of
docks. Two docks need three rules. Three docks need seven, and that table will rot.

Replace it with: every dock width variable defaults to `0px`, each is set to its
`clamp()` only by the rule that fires when that dock is up, and the total is one sum.

```css
html.wfs-windowed {
  --wfs-chat-width: 0px;
  --wfs-panel-width: 0px;
  --wfs-transcript-width: 0px;
  --wfs-docked-width: calc(
    var(--wfs-chat-width) + var(--wfs-panel-width) + var(--wfs-transcript-width)
  );
}
```

One rule covers every combination. Each dock's inboard offset is the sum of the docks
outboard of it, which is why `DOCK_IDS` is ordered:
`--wfs-panel-right: var(--wfs-chat-width)`, and
`--wfs-transcript-right: calc(var(--wfs-chat-width) + var(--wfs-panel-width))`.

Still two docks after this phase. Still right side only. **Behaviour must be
identical.**

Gate: `verify:live` reproduces the pre-Phase-2 numbers exactly. This is the strictest
gate in the release. If a pixel moved, stop.

Traps:
- The fullscreen rules that collapse a dock to `0px` must still win. The width
  selectors in `YT_DOCKS[dock].widthSelector` are one class short of the fullscreen
  ones on purpose. Read the comment on `getDockWidthCss` before touching either.
- Never size from `100vw`. It includes the scrollbar. Size from insets. This trap is
  in `AGENTS.md` and it has already caused a bug once.
- `!important` is required throughout the active-mode sheet, because YouTube sizes the
  player with inline styles from its own JS.

### Phase 4 — transcript dock

Numbered 4 because Phase 3 was the left-side docks, which are dropped. Kept numbered
so the phases match what was agreed.

Structurally this is §3 only: a `transcript` entry in `YT_DOCKS`, its rules in
`YT_ACTIVE_MODE_CSS`, and a selector for the transcript panel. If Phase 2 was done
properly nothing outside §3 needs to change, and that is the test of whether Phase 2
was done properly.

The one hard part: YouTube mounts the transcript in an engagement panel inside
`#secondary`, and the mode sets `#secondary` to `display: none`. So the panel is
invisible in the mode today and you cannot simply dock it. That one panel has to be
un-hidden while the rest of `#secondary` stays hidden. It is fiddly and it is site
knowledge, so all of it belongs in §3.

Note the existing alternative answer for a control whose result renders outside the
player: `YT.pageDependentControls` plus `onPointerCapture`, which stands the mode
down. That is the cheap escape hatch if docking proves unworkable, but it is not the
feature — it is the opposite of it.

Gate: `verify:live` asserts the transcript dock's edge, and the two existing docks are
unmoved.

### Phase 5 — channel profiles

`ChannelRule` already carries `scrollable`, `panel` and `dockWidths`; nothing reads
them yet. Make `autoApplyWanted` in §9 read the matched rule via `findChannelRule`
instead of asking a boolean, and have the mode come up in the layout the rule asks
for. A rule with `scrollable: null` follows the site preference, which is why null
exists rather than a copy of the site value.

`renderChannelRules` in §11 grows a control per field. Today it renders id and Remove
only.

Pure decisions, so they go in `tests/pro-features.test.ts`. No browser needed.

### Phase 6 — letterbox colour, then glow

Colour first, in that order and for a reason: it is one custom property, and it proves
the paint layer sits in the right place and disappears correctly in browser
fullscreen. Glow then reuses the same layer.

Glow needs a repeating read of the video, and invariant 5 is suspicious of loops.
Give it a written budget in the code and a named constant per number:

- Draw into a small offscreen canvas, on the order of 16×16, rather than reading the
  full frame. `getImageData` over a 4K canvas copies 33 million bytes.
- Sample a few times a second, not per frame.
- Stop while the tab is hidden. Stop in browser fullscreen.
- Stop for good after a few consecutive tainted or black reads, so protected playback
  costs nothing. `captureVideoFrame` in §9 already documents that a rental either
  throws on read or returns pure black, and that the two are indistinguishable.
- Never touch layout from the sampler. See the failure note in §4 below.

Gate: `verify:live` asserts the paint layer sits behind the video and is gone in
fullscreen. Check a rental by hand.

### Phase 7 — capture options, then the four free items

`captureFilename` is already pure and already tested, so the template and the burned
timestamp extend existing tests rather than needing new machinery.

Then: copy link at the current time, export and import settings, cursor auto-hide,
and `.ytp-endscreen` added to the rule that already hides `.ytp-ce-element`.

Notes that save time:
- `video.currentTime` is not read anywhere in the codebase today.
- `navigator.clipboard.writeText` is never called. The only clipboard use is
  `copyBlobToClipboard`, which writes a `ClipboardItem` image.
- `downloadBlob` in §9 already exists and is reusable for the settings export. It uses
  a detached `<a download>` deliberately, not `chrome.downloads`, which would add a
  permission warning.
- Import needs `normalizeSitePrefs` exported. It is currently module-private.
- There is already pointer-proximity plumbing for the masthead reveal, which is the
  closest existing thing to cursor auto-hide.

### Phase 8 — surfaces and words

- §11 renders one settings tree into **two** hand-written stylesheets. A CSS fix lands
  in both `public/options/index.html` and `public/popup/index.html` or it has not
  landed.
- New `HELP_COPY` strings must pass `tests/help-copy.test.ts`: 140 characters per
  string, 20 words per sentence, no jargon from `JARGON_LIST`, and no site named. The
  test is property-based, so it needs no editing when copy changes — only when a rule
  is broken.
- `HELP_COPY.pro.body`, `pitchLead` and `features` still describe three features.
  Rewrite for nine.
- Then `AGENTS.md`, `CHANGELOG.md`, `README.md`, `store-assets/LISTING.md`, the
  published listing, and fresh screenshots via `npm run store:assets`.
- `README.md` and `LISTING.md` still say `$5`.

## 4. Standing rules for this release

Drawn from `AGENTS.md`. Repeated here only because they are the ones this particular
release is most likely to break.

- Any new mutation in `enter()` gets its capture added to `LayoutSnapshot` in the same
  commit. Glow adds a layer, so this applies to it.
- Any new loop gets an attempt cap and a `DIAGNOSTIC` code. The glow sampler is the
  one to watch.
- Every new paid surface asks `isPro(pro)` at exactly one place and never stores the
  answer. There are 16 call sites today; they all follow `watchProState`.
- Nothing that was free may move behind the paywall. All nine paid items are new work,
  so this is safe by construction — keep it that way.
- Every new magic number is a named constant with a comment justifying its value.
- Site knowledge lives only in §3. The transcript selectors are the test of this.
- No new permission, no new host permission, no new network call.

**The specific failure to fear.** YouTube strips `ytp-big-mode` when it re-measures,
which leaves its smallest control bar: a squashed scrubber with the buttons crammed
into a corner. It is caused by making the site re-measure too often. So the glow
sampler must never touch layout, and the dock work must keep `refreshGeometry` on drag
**end** only, never per pointer move.

## 5. Payment provider, and why the tree is in test mode

**Do not flip `DODO_API_BASE` or `PRO_PURCHASE_URL` to live during development.** Test
mode is correct until the release commit. Working against live keys means buying the
product to test it, which is a real charge with real processor fees and a refund to
file. It is not illegal, it is just wasteful and slow.

This was got wrong once during 2.0.0 and the fix is worth understanding, because the
guards used to contradict each other. Three things asserted liveness: two tests in
`tests/entitlement.test.ts`, the bundle scan in `scripts/package.mjs`, and the
`Package` step in CI, which ran on every push to every branch. So test mode made both
`npm test` and CI red on every commit that was not a release. A permanently red check
is one nobody reads, which is intolerable across a release this size.

How it works now:

- `scripts/package.mjs` is the release gate and it is **absolute**. It searches the
  emitted bundle for both test hosts, so it reads what the build actually produced
  rather than what the source says, and the zip it writes is the only thing that can
  be uploaded. **Never make this conditional.** Verified working: it currently refuses
  with `[package] refusing: this build uses the provider's test licence API.`
- `tests/entitlement.test.ts` asserts only that the two constants are in the **same**
  mode. That covers the one failure nothing else sees: a live API host with a test
  checkout link sends a buyer to a page that accepts a test card, charges nothing, and
  issues a key the live host will never recognise, with no error anywhere.
- The CI `Package` step runs on `v*` tags only.

**Still to do at the provider, at release time and not before:** create the $10 product
in live mode and put its checkout URL in `PRO_PURCHASE_URL`. Test-mode and live-mode
product ids differ, so the current id cannot simply be moved to the live host.

### Release sequence

1. Flip `DODO_API_BASE` and `PRO_PURCHASE_URL` to live, in one commit.
2. Confirm `manifest.json` and `package.json` both read `2.0.0`.
3. `npm run check`
4. `npm run verify:live`
5. `npm run package`
6. Tag `v2.0.0`.
7. Delete `release/windowed-fullscreen-v1.4.0.zip`. It was never uploaded and it is a
   1.4.0 artifact that should not survive. `package.mjs` refuses to overwrite an
   existing zip, so it will not collide, but it should not be there to upload by
   mistake either.

## 6. How to verify anything in this file

Run these from `windowed-fullscreen-extension/`.

```
npm run typecheck     # tsc --noEmit, the primary gate
npm test              # node:test, no browser or network
npm run build         # emits extension/
npm run check         # all three
npm run verify:live   # layout against a real YouTube page. Needs Chrome. Not in CI.
```

Navigate `src/windowed-fullscreen.ts` by section marker (`§3`, `§7`), never by line
number. The section index is in the file header. The file is around 11,000 lines and
line numbers in any document, including this one, go stale immediately.
