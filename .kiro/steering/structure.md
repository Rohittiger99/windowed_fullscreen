# Structure

The repository root is a container. **The project lives one level down in
`windowed-fullscreen-extension/` — run all npm commands from there.**

```
.github/workflows/ci.yml               Typecheck + test + build + package gate
.kiro/steering/                        These files. Workspace-level orientation
windowed-fullscreen-extension/         THE PROJECT
copywriting/  paywalls/                Unrelated skill kits. Not part of the extension
```

## Inside the project

```
AGENTS.md                    READ FIRST. Invariants and the doc contract
docs/                        The depth, split by topic
CHANGELOG.md                 What changed per version
README.md                    For users of the extension
manifest.json                Extension identity. THE version source of truth
src/windowed-fullscreen.ts   ALL extension code, one sectioned file
public/                      Shipped static assets (icons, page HTML shells)
scripts/                     build.mjs, package.mjs, verify-live.mjs
tests/                       Unit tests (node:test, zero dependencies)
extension/                   BUILD OUTPUT. Never edit; never commit
release/                     The upload zip only
store-assets/                Not shipped: listing copy, screenshots, tiles
```

`extension/` is generated by `npm run build`. Editing it is always a mistake — the change
is lost on the next build.

## The one source file

All code is in `src/windowed-fullscreen.ts`, split into numbered sections §1–§14.
**Navigate by section marker (`§3`, `§7`), never by line number.** The file is around
13,000 lines and any line number written into a document is stale within a week.

The section index is in the file header and in `docs/architecture.md`.

## Where to look before editing

`AGENTS.md` carries the nine invariants and a "read before you edit" table that maps the
area you are touching to the `docs/` file covering it. Start there rather than inferring
the design from the code — most of `docs/` is a record of approaches that were tried and
abandoned, and re-deriving them costs a day each.

The three rules worth knowing before you open anything:

- **Site knowledge lives only in §3.** Every YouTube selector belongs to the `YT` object or
  `YT_ACTIVE_MODE_CSS`. Everything else works from a `SiteDescriptor` and must never name a
  site element. **§9 currently breaks this in 19 places**, all of them the transcript and
  capture code from 2.0.0. That is known, recorded in `docs/architecture.md`, and waiting on
  its own commit — do not treat it as licence to add a twentieth, and do not fix it as a side
  effect of unrelated work.
- **No top-level side effects.** The four `start*` functions are the only way anything
  runs. That is what makes the per-surface tree-shaking safe.
- **Never observe a site subtree with `subtree: true`.** YouTube's player subtree mutates
  continuously during playback, so a subtree observer there costs a MutationRecord per
  mutation for the life of the page. This was the main cause of reported lag. Watch the
  specific element whose children matter, and its parent if the site can replace it.
  → `docs/youtube-layout.md`, "Cost"

## Keeping documents true

`AGENTS.md` has a table mapping each kind of change to the documents that must change with
it, in the same commit. Use it. The failure mode this project has actually suffered is not
missing documentation but confidently wrong documentation — a stale doc is worse than no
doc.
